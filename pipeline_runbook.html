LQAS Pipeline

Posit-LQAS-Workflow

Located at C:\Users\TOURE\Documents\Gith_repositories\Posit-LQAS-Workflow. One orchestrator script, run_pipeline.r, runs all seven steps and opens the dashboard when it's done.

01One-command run

Run from the project root. If Rscript isn't on PATH — true of most Task Scheduler and Git Bash sessions on this machine — use the full path instead, exactly as monday_morning.sh and git_sync.sh already do.

Git Bash / PATH has Rscript
$ cd /c/Users/TOURE/Documents/Gith_repositories/Posit-LQAS-Workflow
$ Rscript run_pipeline.r
Full path (no PATH entry)
$ "/c/Program Files/R/R-4.4.1/bin/x64/Rscript.exe" run_pipeline.r --force-full

The orchestrator runs these seven steps in order, then always tries to open 04_dashboard.html — even if a step failed, as long as a dashboard already exists from a previous run:

1Refresh Lookup.py
→
2Data Fetch.py
→
3Process.R
→
4Clean Geonames.R
→
5Dashboard.Rmd
→
6Quality Control.R
→
7SharePoint Push.R

Steps 1 and 7 are non-blocking — a failed lookup refresh (expired GPEI_API_TOKEN) falls back to whatever lqas_lookup.xlsx is already on disk, and a failed SharePoint push doesn't stop the rest of the run.

02Flags

--force-full
Makes step 2 refetch every ONA form. Without it, any form whose raw file already exists on disk is skipped — a scheduled run can go weeks without pulling fresh survey data.
--debug
Passed through to step 1; saves a fetch summary to data/lookup/refresh_debug/.
--skip-lookup-refresh
Skip step 1 (refresh_lqas_lookup.py).
--skip-fetch
Skip step 2 (fetch_ona_data.py) — reuse whatever's already in data/raw/.
--skip-process
Skip step 3 (R/02_process_lqas.R).
--skip-clean
Skip step 4 (R/03_clean_geonames.R).
--skip-dashboard
Skip step 5 — no 04_dashboard.html is (re)generated.
--skip-qc
Skip step 6 (R/05_quality_control.R).
--skip-sharepoint-push
Skip step 7 — nothing gets published to SharePoint this run.

03Run one step by itself

Both of these are what the orchestrator calls internally — useful when you only need one piece.

Refresh the lookup file only
$ python refresh_lqas_lookup.py --debug
Fetch raw ONA data only
$ python fetch_ona_data.py --force-full
# other flags: --config <path>   --form-ids 4500,6837   --test (connection check only)

04Common recipes

Iterate on processing/cleaning without re-fetching
$ Rscript run_pipeline.r --skip-lookup-refresh --skip-fetch
Just rebuild dashboard + QC from data already processed
$ Rscript run_pipeline.r --skip-lookup-refresh --skip-fetch --skip-process --skip-clean

AFRO-SIA Dashboard Input

input\scope

Located at C:\Users\TOURE\Documents\REPOSITORIES\input\scope. Standalone from the LQAS pipeline above — it shares no files or schedule with it. Run it by hand whenever the dashboard needs fresh scope/admin data.

01Current launcher, and the one to retire

cmd.exe current
> run_prepare_the_AFRO_SIA_Dashboard_input.bat
# same as: python scripts\prepare_the_AFRO_SIA_Dashboard_input.py
legacy — don't use run_download_gpei_scopes.bat

Still on disk, still calls scripts\download_gpei_scopes.py — the old Playwright browser-login flow. It broke for good when GPEI's login page switched to a WHO SSO button with no username/password fields left to automate. Use the launcher above instead; this one is kept only as a fossil.

02What it does

1GPEI API fetchlookup + scopes
→
2SharePoint downloadadmin + LQAS
→
3Build scope_.csvbuild_scope_file.R
→
4Build .rds inputsprepare_dashboard_inputs.R

Step 1 pulls lookup.xlsx and gpei_scopes.csv from poliogo.afro.who.int's own API — campaigns of type "Polio" only, Jan 1 2019 → today by default. Step 2 pulls AFRO_admin_data.xlsx and AFRO_LQAS_data_c.csv from the WHO AF-pep/GISWORKSPACE SharePoint site via Microsoft Graph — no browser, no MFA.

03Flags

--debug
Saves fetch/build/rds output to logs\gpei_debug\.
--start-date / --end-date
Override the default window (2019-01-01 → today). Format YYYY-MM-DD.
--skip-build
Fetch the input files only; skip building scope_.csv yourself.
--skip-afro-download
Skip the AFRO_admin_data.xlsx SharePoint download.
--skip-lqas-download
Skip the AFRO_LQAS_data_c.csv SharePoint download.
--skip-gpei-fetch
Skip the GPEI API step — use when poliogo.afro.who.int is down. Combine with the SharePoint flags above to control what still runs.
--skip-rds
Skip the final .rds conversion — leaves the dashboard's input\ folder untouched.
